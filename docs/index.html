What it does

从发单到结算，一条链路闭环。

不是简单的群消息机器人：订单状态、角色权限、结算批次和群内操作都会被记录、同步和审计。

三种角色，各司其职

管理员全量管理；发单员只发自己的单；合作伙伴在群里接单、完成或标记失败，权限边界清晰。

Telegram 群内接单

订单以卡片形式推送到白名单群，群成员直接点按钮接单、完成或失败，网页状态实时同步。

双层结算，互不干扰

群总账按财务周期结算；发单员私账单独标记，结算后不影响群订单的财务状态。

图片直接粘贴

电脑端发单支持从剪贴板直接粘贴图片，不必先保存再上传；最多 6 张 JPG / PNG / WebP。

失败必须写原因

标记失败时先选择原因，再同步到群；避免只改状态、不留证据，管理员可追溯到具体原因。

中英双语 + 暗色 UI

界面与 Telegram 消息支持中英文；登录页采用深色电影感动效，移动端和桌面端都已适配。

Architecture

三个入口，一套数据。

网页、Telegram 群和结算后台共享同一套订单状态；所有关键操作都落在数据库里。

01

Web 发单

管理员或发单员在网页建单，填写产品、账号、金额、图片和备注；金额为必填项。

Vue 3 · Element Plus
02

群内协作

机器人把订单卡片推送到指定群；接单人点击按钮，状态与失败原因实时回写。

Telegram Bot API
03

结算与审计

群总账和发单员私账分开结算，支持筛选、预览、Excel 导出和完整审计日志。

FastAPI · PostgreSQL
Quick start

Docker 一键起，
五分钟跑起来。

只需要 Docker Engine 24+ 和 Compose v2。脚本会自动生成密钥、构建镜像、执行迁移并初始化管理员。

  • 复制环境变量模板，按需填写 Telegram Bot Token
  • 数据库、后端、前端全部通过 Docker Compose 编排
  • 生产环境请使用 HTTPS 域名，Telegram 按钮回调依赖公网地址
terminal 
git clone https://github.com/Minerchu/orderflow.git
cd orderflow
cp .env.example .env
# 编辑 .env：填写 POSTGRES_PASSWORD / TELEGRAM_BOT_TOKEN
./scripts/deploy.sh
# 完成后访问 http://<server>:80
